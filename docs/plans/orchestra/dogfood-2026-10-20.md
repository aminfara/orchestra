# Dogfood runs: the remaining flows, 2026-10-20

On 2026-10-20 the feature-task, understand, rewrite and new-feature flows each ran on a real codebase, so every flow in the plan has now had a dogfood run. Two runs stopped by choice once their flow-specific phases were done, because what remained was the build flow, which had already been dogfooded on 2026-10-19. The runs exposed three framework defects, all fixed the same day. The heaviest of them: Claude Code now refuses any write from a worktree agent into the project's checkout, which cut engineers and reviewers off from the ledger and the run folder.

## How it ran

Each conductor ran headless in its own persistent session with stream-JSON input, as on 2026-10-18. The overseer session played the user, answered the conductor's batched questions, and read artifacts at the review gates. Two conductor sessions ran in parallel, one per project. A resumer script sent "continue" after each usage-limit reset, and every session resumed from its run log after three limit stops.

The new codebase was Click 8.5.0, the Python command-line library (about 12,700 lines of source and 14,800 of tests), cloned into `~/Workplace/click` with its remote removed so nothing could be pushed. TripSplit carried the feature task and the new feature.

## What went well

The understand flow produced a map a newcomer can work from. Five area architects read the parser engine, dispatch, the value pipeline, shell completion and the support modules in parallel. The parser-engine architect then mutated the parser nine ways and re-ran the suite, and found that five behaviours are pinned by no test. The resulting contract cites file and line for each of its 45 items. The overseer checked three line references and two behaviours (`-n -- -f` and `-o=value`) against the code, and all held.

The rewrite flow kept the understanding and the design in one context, as intended. Its breakdown put the characterisation suite first, and seven parity stories were built and reviewed before any engine code. Reviewers ran differential tests of the new engine's parts against the old one: 500,000 cases for the option phase and 50,000 for the argument phase, with no differences.

The new-feature chain started from the existing documents. The architect who designed CSV export found a milestone 1 defect on the way: the WhatsApp tip looks for "WhatsApp" in the browser's identity string, but WhatsApp marks its browser `WAiOS/` or `WA4A/`, so the tip probably never shows. The defect is now story S-37 on the board.

Gates worked as designed. When the user asked to drop machinery from the PRD (an export "visit" that kept its own copy of the trip), the product manager recorded the comment as a user finding, revised one requirement, and the checker re-checked only that change. When the two-round check limit left two stale lines open, the conductor offered a one-minute fix instead of a third round.

## The defects, and the fixes

**Worktree agents cannot write into the project.** Claude Code now refuses any write from a worktree-isolated agent into the shared checkout. The Write tool is refused by a hook, `git -C` by the harness, and scripts by the auto-mode classifier as "Modify Shared Resources". The classifier was not consistent: it let one reviewer's `feedback.py` calls through and refused the same kind of call from a probe agent. In the feature task the engineer could not write its report, notes or ledger records, and the conductor wrote them from the agent's final message. Fix: engineers and reviewers now write into `.orchestra/outbox/` in their own worktree, which mirrors the project's `.orchestra/` folder. `feedback.py record` and `resolve` take `--outbox`, `feedback.py import` copies an outbox's events and run files into the project, and the subagent-stop hook imports the outbox before it checks the ledger IDs a verdict cites. In the rewrite build, all 32 events in the outboxes of the five worktrees left at the end had reached the ledger through the hook.

**A hand-written ledger line broke every reader.** An engineer briefed before the outbox existed appended a JSON line with no `type` or `ts` to the ledger with `echo`. `close-run` then failed, and the subagent-stop hook would have stopped recording agents and checking cited IDs without saying so, because a hook never breaks a session. The conductor removed the line. Fix: ledger readers skip lines that are not events, `count` reports how many it skipped, and `import` reports the ones it left out of an outbox.

**Worktrees piled up.** TripSplit held 32 agent worktrees from earlier runs, and the feature task's conductor had to remove one by hand to free the story's branch. Fix: when a run closes, the conductor imports each of its worktrees' outboxes and removes the worktrees with `git worktree remove`, without `--force`. Git keeps the branches and refuses a worktree with uncommitted work, which the conductor leaves and names in the log.

## Cost

The engineers' contexts fell to about a third of the 2026-10-19 build's. Click's engineers re-read 52.6 million cached tokens over 25 stops (2.1 million a stop, with a peak context of 114,000), against 309 million over 47 stops (6.6 million a stop, peaking at 278,000) in TripSplit's build. Smaller stories and a fresh instance per story explain most of it; in the feature task, a fresh engineer briefed from notes peaked at 104,000. Architects are now the heaviest role: 132 million over 29 stops, peaking at 242,000, mostly across the understand and rewrite design phases.

Two conductors in parallel used a 5-hour Pro window in about 1.5 hours of wall time.

An analysis of the 2026-10-19 engineer transcripts found no single kind of tool output behind the context growth. End-to-end test runs added about 2,000 tokens each. The growth was spread over about 2,000 small shell and read calls, so the cost comes from the number of calls multiplied by the context size.

## Left for the coach

These are for a retro to weigh with the ledger's evidence, not fixes made now:

- The cause the first retro named recurred after its concept changes landed: an author built or tested the case in front of it and assumed the rest would follow. Examples in the rewrite run include S-1's shared test harness, built for S-1's own fields without walking the later stories that use it (two high findings), and an architect who mapped the parser's consumers by the import graph and missed the code that splits tokens before the parser sees them.
- A small feature got a large specification: the CSV export's first PRD carried "visit" rules that the user removed at the gate.
- The conductor read "you don't need to stop before the build" as approval of the breakdown gate. It recorded the reading and asked to be corrected; the user's message was ambiguous, so this is one instance and not yet a pattern.
